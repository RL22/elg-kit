# Product Requirements Document (PRD): `elg-kit`

> Employee-Led Growth rails: open-source toolkit and universal agent skill for high-growth tech teams.

---

## Problem Statement

Technical companies want organic distribution on professional networks, but existing employee advocacy workflows fail in three predictable ways:

1. **The Corporate Cringe Penalty:** Legacy advocacy software asks employees to blast identical corporate copy. This triggers social network spam filters and destroys the employee's personal credibility with peers.
2. **The Attribution Void:** Marketing leaders cannot measure pipeline generated by employee posting without forcing employees to build manual UTM links. When generating a link takes more than five seconds, employee adoption drops to zero.
3. **The Algorithm Link Penalty:** Modern social algorithms cut the distribution of posts with external links by 40% to 60%. Employees either omit company links entirely or include raw links that hurt post reach.
4. **The Security and Governance Exposure:** Unrestricted open redirect shortlinks risk phishing abuse under trusted corporate domains, while uncurated pull request ingestion leaks confidential product roadmaps.

---

## Solution

`elg-kit` provides lightweight, developer-first rails for Employee-Led Growth. An admin deploys the system once in five minutes. Employees interact with the system entirely through Slack and fast edge redirects.

The product combines four hardened subsystems:
- **Signal Ingestion and Curation Gate:** An ingestion pipeline with HMAC signature verification that parses GitHub, Linear, and webhook events into candidate milestones, guarded by an editorial release gate to prevent leaking unannounced features.
- **Perspective Engine:** An agent running on Vercel Eve that derives five distinct role angles (Builder, GTM, Talent, Visionary, Product) while matching individual employee writing styles and stripping corporate hype.
- **Hardened Edge Redirect Router:** A Cloudflare Worker providing sub-5ms redirects (`go.company.com/e/:member`) with strict domain allowlists, bot crawler filtering, and comment-first link delivery to protect social reach.
- **Slack Showcase and Peer Review Hub:** A decentralized collaboration space in Slack supporting pre-publish technical reviews, one-click personal link generation for teammates, thread quote harvesting, and collective milestone celebrations.

## User Stories

### Persona Definitions
- **Admin / Growth Lead:** Head of Growth, Developer Relations Lead, or Founding Engineer configuring and monitoring the system.
- **Builder / Engineer:** Software engineer or product designer who ships features and wants to share technical learnings without corporate jargon.
- **Seller / GTM Lead:** Account Executive, SDR, or Product Marketing Manager who wants to share customer problem-solving narratives.
- **Recruiter / Talent Lead:** Talent partner highlighting engineering culture and open roles tied to actual shipped work.
- **Peer Reviewer:** Colleague verifying technical accuracy and safety before content goes public.

### User Stories

1. As an Admin, I want to initialize the entire system using `npx create-elg-kit`, so that I can configure Slack, Cloudflare, and signal webhooks in under five minutes.
2. As an Admin, I want to paste a pre-configured Slack App Manifest into api.slack.com, so that I avoid manually configuring scopes, bot events, and slash commands.
3. As an Admin, I want incoming webhooks verified with HMAC SHA-256 signatures and timestamp replay checks, so that attackers cannot forge events or trigger unauthorized model spend.
4. As an Admin, I want the edge router to enforce a strict destination domain allowlist (`company.com` and approved subdomains), so that malicious actors cannot use our domain as an open redirect for phishing.
5. As an Admin, I want crawler bots and link preview unfurlers filtered at the edge, so that automated scrapers do not inflate employee click statistics.
6. As an Admin, I want an editorial staging queue (`#elg-staging`), so that internal leads approve which major product releases prompt employee creator DMs.
7. As a Builder, I want to receive a private Slack DM when a major feature I authored is released, so that I am reminded to share my work without public channel pressure.
8. As a Builder, I want the bot DM to provide technical post angles focused on architecture tradeoffs, so that I avoid staring at a blank screen.
9. As a Builder, I want the bot to deliver my post copy without links and provide my attributed link separately for comment #1, so that social algorithms do not penalize my post reach.
10. As a Builder, I want my attributed link (`go.company.com/e/rodney`) generated automatically without filling out UTM forms, so that I can post in under 30 seconds.
11. As a Builder, I want to submit three sample posts once via Slack, so that the agent matches my personal cadence, vocabulary, and sentence length.
12. As a Builder, I want the agent to strip corporate buzzwords, rhetorical questions, and rocket emojis from drafts, so that my posts read like an authentic engineer rather than a marketing department.
13. As a Builder, I want to click `[ Request Peer Review ]` inside Slack, so that colleagues can verify my technical accuracy and confirm no private customer data is exposed before I publish.
14. As a Seller, I want the system to generate a customer-problem angle for every approved release, so that I can explain business impact to buyers without listing raw technical specifications.
15. As a Recruiter, I want the system to pair technical shipments with active job openings, so that candidates see evidence of team velocity in my posts.
16. As an Employee, I want to type `/link <destination-url>` in any Slack channel, so that I instantly get my personal attributed shortlink for original posts.
17. As an Employee, I want to type `/angles` in Slack, so that I can browse recent company milestones and talking points when I am ready to write an unprompted post.
18. As an Employee, I want to click `[ Share to #showcase ]` when my post is live, so that my team can see what I wrote without flooding the main channel.
19. As a Teammate, I want a `[ 🔗 Get My Attributed Link ]` button on every shared showcase card, so that I can reshare a colleague's post using my personal attribution in one click.
20. As a Teammate, I want discussions and praise contained in thread replies, so that the main showcase channel remains clean and readable.
21. As an Employee, I want frequency caps that limit proactive bot DMs to at most once per week, with simple snooze and opt-out commands, so that the bot never feels like spam.
22. As an Employee, I want to receive a private weekly Slack digest showing how many verified readers clicked my links, so that I know my posts produce measurable interest.
23. As an Admin, I want click metrics logged to Cloudflare Analytics Engine without maintaining an external database, so that our running infrastructure costs remain zero dollars.

## Implementation Decisions

### Module 1: Admin CLI (`create-elg-kit`)
- Distributed via npm.
- Guided terminal prompts collect Slack bot tokens, signing secrets, Cloudflare API credentials, and target edge hostname (`go.company.com`).
- Enforces configuration of allowed target domains (for example: `company.com`, `docs.company.com`).
- Generates a tailored `slack-manifest.json` file ready for one-click import into the Slack API dashboard.
- Executes automated `wrangler deploy` to publish the edge redirect worker directly to the admin's Cloudflare account.

### Module 2: Hardened Edge Redirect Worker (`packages/edge-redirect`)
- Built as a stateless Cloudflare Worker script.
- Route pattern: `go.company.com/e/:member?url=<destination_url>`.
- Request processing pipeline:
  1. Extract `:member` slug from pathname.
  2. Parse target URL from query parameters (defaulting to primary company root if omitted).
  3. Validate target hostname against strict configuration allowlist. Reject unauthorized hostnames with HTTP 400 Bad Request to prevent open redirects.
  4. Inspect `User-Agent` header to detect automated preview scrapers (Slackbot, Twitterbot, LinkedInBot, Googlebot). If a bot is detected, redirect immediately without incrementing analytics counters.
  5. Append standard tracking tags: `utm_source=linkedin`, `utm_medium=elg`, `utm_campaign=:member`, and a unique click identifier (`elg_cid`).
  6. Emit asynchronous click data point via `ctx.waitUntil(env.ANALYTICS.writeDataPoint(...))`.
  7. Return HTTP 302 Found response with `Location` header in under five milliseconds.

### Module 3: Agent Orchestration Core (`apps/agent` using Vercel Eve)
- Filesystem-first agent architecture built on Vercel Eve:
  - `agent/instructions.md`: Declares persona rules, anti-cringe filters, and banned vocabulary.
  - `agent/channels/slack.ts`: Implements Slack event subscriptions, slash command routing (`/link`, `/angles`, `/showcase`, `/elg`), and modal workflows.
  - `agent/tools/voice-profiler.ts`: Retrieves and stores member writing samples using Eve durable key-value memory.
  - `agent/tools/signal-parser.ts`: Normalizes incoming release payloads into standardized milestone records with HMAC signature verification.
  - `agent/schedules/weekly-impact.ts`: Runs scheduled Friday cron job to query Cloudflare Analytics Engine and send 1:1 impact recaps to active members.

### Module 4: Perspective Engine (`packages/elg-engine`)
- Houses the quintuple-perspective system prompt templates.
- Input: Standard milestone payload containing title, changelog summary, git author metadata, and issue reference links.
- Output: Structured JSON payload with five isolated perspectives:
  - `builder`: Technical architecture, trade-offs, performance numbers, and internal edge-case discoveries.
  - `gtm`: Business pain solved, operational metrics improved, and buyer relevance.
  - `talent`: Engineering velocity demonstration, team culture, and relevant open roles.
  - `visionary`: Strategic industry shift, category creation narrative, and contrarian thesis on software evolution.
  - `product`: User workflow friction eliminated, usability trade-offs, and human day-to-day impact.
- Shared format: Packaged simultaneously as an internal TypeScript library for Vercel Eve and an open-standard Agent Skill (`~/.agents/skills/elg-engine/SKILL.md`) for standalone CLI use in Antigravity, Claude Code, and Codex.

### Module 5: Anti-Cringe and Tone Engine
- Prompt-level and post-processing regex filters enforce strict editorial standards:
  - Filter out corporate hype terms, promotional clichés, and hollow transitions.
  - Strip forbidden emojis: rocket, fire, party popper, flexing bicep.
  - Enforce character-count budgets suited for native social readability (150 to 300 words).
  - Format output into two separate blocks: `post_body` (strictly link-free) and `first_comment` (containing the `go.company.com/e/:member` URL).

### Module 6: Showcase and Peer Review Hub
- Central Slack space for internal visibility, peer review, and collective celebration:
  - **Pre-Publish Technical Review Modal:** Authors can request peer review. Colleagues review drafts using a structured modal checking technical accuracy and confirming no private customer data is exposed.
  - **Author-Initiated Showcase:** Published posts appear in `#showcase` only when an employee explicitly triggers `/showcase` or clicks a share button.
  - **Thread-Only Engagement:** All comments, discussions, and high-fives remain strictly confined to the post's thread.
  - **One-Click Teammate Link:** Cards include a `[ 🔗 Get My Attributed Link ]` button, allowing any colleague to reshare the story with their personal tracking slug instantly.
  - **Thread Quote Harvesting:** The bot identifies insightful engineering discussions in threads and offers to synthesize them into follow-up post drafts.
  - **Team Milestone Celebrations:** Public alerts in `#shipped` celebrate collective volume (for example: "Team reached 1,000 developer reads this week across eight posts") rather than individual stack-ranked leaderboards.

## Testing Decisions

### What Makes a Good Test
Tests must verify external behavioral contracts, network routing, and payload delivery rather than internal implementation details. Tests should never mock the core redirect logic or the prompt formatting schemas.

### Module Test Matrix

1. **Edge Redirect Worker (`packages/edge-redirect`):**
   - Verify that requests with valid allowlisted URLs return a 302 redirect with correct UTM parameters appended.
   - Verify that requests targeting off-domain or unauthorized URLs return an HTTP 400 Bad Request.
   - Verify that bot user-agents (Slackbot, LinkedInBot) receive immediate redirects without logging analytics data points.
   - Verify that click telemetry execution inside `ctx.waitUntil` does not block or increase redirect response latency beyond five milliseconds.
   - Test suite: Vitest running against Cloudflare Miniflare / workerd runtime.

2. **Perspective Engine (`packages/elg-engine`):**
   - Verify that incoming release notes produce valid JSON matching the five role schemas (`builder`, `gtm`, `talent`, `visionary`, `product`).
   - Verify that the anti-cringe filter rejects posts containing banned vocabulary or forbidden emojis.
   - Verify that generated `post_body` contains zero HTTP links and that all links reside exclusively in `first_comment`.
   - Test suite: Node test runner with deterministic mock model completions.

3. **Slack Channel and Ingress (`apps/agent`):**
   - Verify `/link` slash command returns personal shortlink for the calling Slack user ID.
   - Verify that webhook endpoints reject payloads with missing or invalid HMAC signatures.
   - Verify that proactive DMs obey frequency caps and respect employee snooze/opt-out settings.
   - Test suite: Mock Slack Bolt client checking dispatched chat payloads.

## Out of Scope

- **Automated Posting to Social Networks:** `elg-kit` will never automatically post on an employee's behalf using social media APIs. The human must copy, review, and publish their own content.
- **External Engagement Pods:** The system strictly excludes coordinated external commenting swarms or automated engagement groups to comply with LinkedIn and X platform authenticity policies.
- **Direct CRM / Salesforce Deep Sync:** The system will not include native Salesforce or HubSpot OAuth integrations in v0.1. Enterprise deal notifications enter via the generic `/api/signals` webhook.
- **Individual Stack-Ranked Leaderboards:** The product excludes public zero-sum leaderboards to prevent vanity metrics and internal competition. All team recognition is collective, qualitative, or delivered via private 1:1 Slack DMs.
- **Native Mobile Applications:** Interactions occur entirely inside existing Slack desktop and mobile clients.
